Reference

Glossary

The course's vocabulary. Each term is used in exactly this sense on every page.

Actual
What your code really returned. In assert actual == expected it goes on the left; in the pandas comparison functions it is the first argument, reported as [left]. Lessons 1, 3
Assertion
A single check. Usually one assert statement; also one call to a helper such as pd.testing.assert_frame_equal(), or one pytest.raises() block. It is silent when it passes and raises an error when it does not. Lesson 1
Collection
The first thing pytest does in a run: it searches for test files and gathers the tests inside them. The report line collected 3 items says how many it found. Lesson 2
Dependency
Another package that yours needs. Packages your functions need are listed under dependencies in pyproject.toml; packages only your tests need go in a dependency group. Lesson 5
Edge case
An input at the boundary of what a function was written for: missing values, an empty column, a constant column, the wrong type. Lesson 4
Editable install
Installing your own package with pip install -e ., so that Python imports it straight from your project folder and every edit takes effect without reinstalling. Lesson 5
Expected
What the code should return, worked out by you and typed into the test. In assert actual == expected it goes on the right; in the pandas comparison functions it is the second argument, reported as [right]. Lessons 1, 3
Failure
A test in which an assertion did not hold. Either the code or the test is wrong; the report helps you decide which. Counted as failed on the last line of the report. Lessons 1, 2
Happy path
Ordinary, well-formed input producing an ordinary result. The first thing to test, never the only thing. Lesson 4
Package
Python's standard way to bundle functions and their settings in one folder with a fixed layout, so that the code can be installed and then imported from anywhere. Lesson 5
pyproject.toml
The settings file at the top of a package. It gives the package's name, lists the packages it depends on, and holds pytest's settings. Lesson 5
pytest
The Python package this course uses for unit testing. It finds your tests, runs them, and reports what happened. Lessons 1, 2
Regular expression
A text pattern. The match argument of pytest.raises() and pytest.warns() takes one and checks that the message contains it; re.fullmatch() checks a whole string against one. A plain phrase such as "must be a numeric column" is the simplest kind. Lessons 3, 4
Test
One function whose name starts with test, holding one or more assertions about a single behaviour. Lesson 2
Test file
A Python file in tests/ whose name starts with test_. It holds the tests for one file of functions. Lesson 2
Test name
The name of a test function, written so that it says what the code should do. It is printed when the test fails. Lesson 2
Tolerance
The small numeric difference that pytest.approx() and the pandas comparison functions ignore, so that floating-point noise does not cause failures. A bare == has none. Lessons 1, 3
Unit test
A check, written as code, that one small piece of a program (usually one function) behaves as intended. Lesson 1
Virtual environment
A private set of installed packages for one project, kept in a folder such as .venv/. It has to be activated in each new terminal. Lesson 5

Definitions follow the usage in the pytest documentation and the Python Packaging User Guide. See also the cheat sheet.
