Anatomy of a test

Assertions are grouped into tests; tests are organised in files. A passing assertion is silent. (Lesson 1, Lesson 2)

Test file names must start with test_ and end with .py; test function names must start with test. Useful switches: -v lists every test, -x stops at the first failure, --lf reruns only the tests that failed last time. (Lesson 2, Lesson 5)

Reading the report

Then decide which side is wrong: the function or the test. A test stops at its first failing assertion. ModuleNotFoundError: No module named 'clean' means Python could not find your functions: run python -m pytest from the project folder, or in a package, activate the environment and install.

Habits

  • Work out the expected value yourself. Never compute it by calling the function under test.
  • Small inputs. Three rows you can check in your head are worth more than three thousand you cannot.
  • One behaviour per test, with a name that says what should happen and that no other test shares.
  • Each test builds what it needs. No test depends on another.
  • Walk the edge cases: missing values, all values the same, a single value, empty input, the wrong type.
  • Bug found? Test first. Write a test that fails, fix the code, run all the tests.
  • Prefer the specific check to .equals() or pytest.raises(Exception).
  • See every test fail once. A test that has never failed has not shown it can.
