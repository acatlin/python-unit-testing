Test functions and test files

An assertion typed at the console is gone when you close Python. This lesson gives your assertions a name, a file, and one command that runs all of them.

By the end you can

Lay out a Python project with a tests/ folder, run every test with one command, and read the report.

From last time

Two questions from Lesson 1. Answer before reading on; recalling is what makes it stick.

  1. What does a passing assert statement print at the console?

    • Nothing at all.
    • The word True.
    • A green tick.
    • The compared values.

    Assertions are silent when they pass.

  2. Which pytest helper makes == ignore tiny floating-point differences?

    • pytest.approx()
    • pytest.equal()
    • pytest.close()
    • pytest.exact()

    Wrap the expected value: actual == pytest.approx(expected). A bare == has no tolerance. The other three do not exist.

Group assertions into a test

A test is a function whose name starts with test. It takes no arguments, returns nothing, and holds one or more assertions about a single behaviour.

Defining the function runs nothing. You do not call it yourself either: pytest finds it by its name and calls it for you, as you will see below.

The name is the description. When a test fails months from now, its name is the first thing you will read, so make it say what the function should do, not just the function's name. test_rescale01 tells you where to look; test_rescale01_maps_smallest_to_0_and_largest_to_1 tells you what broke. Long names are normal here, because nobody ever has to type them again.

pytest collects “test prefixed test functions or methods outside of class”. pytest, “Conventions for Python test discovery”. “Good tests make it clear what they are testing and how.” Scientific Python Development Guide.

Give tests a home

Tests live in their own files, apart from the code they test. The layout below keeps the tests in a folder of their own, which pytest's documentation calls “often a good idea”, and it is the one Python packages use, so learning it now saves relearning it later.

cleaning-project/
├── clean.py              your functions
└── tests/
    └── test_clean.py     tests for the functions in clean.py

Two rules matter. pytest looks for files whose names start with test_ and end with .py (it also accepts names that end with _test.py; this course uses the first form), and inside them for functions whose names start with test. A file called clean_tests.py is not treated as a test file, and a function called check_rescale01() is not treated as a test. pytest skips both without a word.

pytest will “search for test_*.py or *_test.py files”. pytest, “Conventions for Python test discovery”. The pairing clean.py ↔ test_clean.py: “Test files should be named test_{file under test}.py”, Scientific Python Development Guide.

So there are three levels, each inside the next: assertions are grouped into tests, and tests are organised in files.

Here is tests/test_clean.py. It tests three small cleaning helpers that live in clean.py.

What is from clean import …?

A test file is an ordinary Python file, so it has to import everything it uses. That includes your own functions: the line from clean import clean_names, parse_money, rescale01 fetches them from clean.py. Treat it as a line every test file starts with, and add to it when you test another function.

Run everything

Open a terminal in the project folder, the one that contains clean.py, and run one command. A terminal is your computer's command line, not the Python console: there is no >>> prompt. Most editors have one built in, and it usually opens in the folder you have open in the editor.

pytest searched the folder, found one test file and collected three tests from it. Each row is one test file, with one dot for each test that passed. Note what is being counted: 3 is the number of tests, not the number of assertions (6) or files (1).

Why python -m pytest and not just pytest? The test file says from clean import …, so Python has to know where clean.py is. Starting pytest through python -m adds the folder you are standing in to the places Python looks. In a plain project, that is your job; Lesson 5 takes it away.

“This is almost equivalent to invoking the command line script pytest [...] directly, except that calling via python will also add the current directory to sys.path.” pytest, “How to invoke pytest”.

Add -v (for verbose) and pytest lists every test by name. This is where good names start to pay.

Reading a failure

Suppose you had typed the expected name as "zip-code". The report becomes:

Read it in three steps. What: the banner under FAILURES is the name you gave the test. Where: the > marks the line that failed, and tests\test_clean.py:13 gives the file and line number. Why: the lines that start with E. pytest has filled in both sides of the == for you, the actual value on the left and the expected value on the right, and it says where they first differ. Then decide which side is wrong. Here the function is fine and the test was mistyped, and that happens more often than you would think.

pytest's “assertion introspection will intelligently report intermediate values of the assert expression”. pytest, “Get Started”.

One more thing to know when reading a report: a test stops at its first failing assertion. Any assertions below it in the same function did not run, so they may be hiding more failures.

“a test stops at the first failing assertion, which gives you an incomplete picture if a later behavior is also broken.” Scientific Python Development Guide, “Test” tutorial.
Common trap

If the run stops with ModuleNotFoundError: No module named 'clean', nothing is wrong with your tests. Python could not find clean.py: you typed pytest on its own, or you ran the command from a different folder. Go to the project folder and run python -m pytest.

Try it

  1. Get the starter project: on the repository's front page choose Code, then Download ZIP, unzip it, and copy the folder examples/cleaning-project-starter somewhere of your own. Or build the two files by hand: copy clean.py from that page and type the test file above, which is good practice. You need pandas and pytest installed.
  2. Open a terminal in the project folder and run python -m pytest. You should see 3 passed.
  3. Add a third assertion to the parse_money() test, for the input "$3,000", and run again. The count is still 3, because pytest counts tests. Now move that assertion into a new test of its own, with a name that says what it checks, and watch the count become 4.
  4. Rename the test file to clean_tests.py and run again. You should see collected 0 items and no tests ran. Rename it back.

Check yourself

  1. What makes a Python function a test that pytest will find and run?

    • Its name starts with test.
    • Its body contains an assert.
    • Its first argument is pytest.
    • Its docstring mentions the test.

    pytest goes by the name alone. A function full of assertions but named check_rescale01() is never run.

  2. Which of these files in tests/ will pytest collect tests from?

    • test_clean.py
    • clean_tests.py
    • check_clean.py
    • clean.py

    Test file names must match test_*.py (or *_test.py). clean_tests.py, with an s, matches neither and is silently skipped.

  3. A run stops with ModuleNotFoundError: No module named 'clean'. What is the likeliest cause?

    • Python could not find the file clean.py.
    • The test file has the wrong name.
    • The pytest package is not installed yet.
    • The expected values were typed in wrong.

    In a plain project, run python -m pytest from the project folder so that the folder is on Python's search path. A misnamed test file would not be collected at all, so it could not produce this error.

  4. A run ends with 1 failed, 2 passed. What happened?

    • Two tests passed and one failed.
    • Two files passed and one failed.
    • Two assertions passed and one failed.
    • Two tests passed and one skipped.

    The summary counts tests. Those three tests might hold six assertions, and a test with one failing assertion counts as one failure.

  5. Why run python -m pytest instead of plain pytest in a plain project?

    • It puts the current folder on Python's path.
    • It runs every test file three times over.
    • It hides the report unless a test fails.
    • It installs pandas and pytest before each run.

    That is what lets from clean import … find clean.py. Everything else about the two commands is the same.
